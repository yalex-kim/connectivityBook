# 영상 제작 규칙

ConnectivityBook 내용으로 영상을 만들 때 따르는 규칙이다. 첫 영상("블루투스는 왜 AFH가 필요할까")을 만들며 받은 피드백을 정리했다. 새 영상도 이 순서와 기준으로 만들고, 규칙을 바꿀 일이 생기면 이 문서를 먼저 고친다.

## 1. 진행 순서

1. **주제와 메시지 정하기**: 책의 한 장에서 "왜 그런가"를 하나 고른다. 숫자 하나가 아니라 원리·메커니즘이 메시지가 되게 한다(예: "42%를 잃는다"가 아니라 "AFH가 왜 필요한가").
2. **훅 제안 → 선택**: 훅 후보를 여러 개 내고 사용자가 고른다. 실제 생활 장면(기기들을 함께 쓰는 방 등)으로 여는 것이 잘 맞았다.
3. **구성안 검토**: 장면별 화면·나레이션을 표로 정리해 확인받는다.
4. **무음판**: 화면과 자막만으로 렌더해 보여 준다. 고칠 점을 받아 반영한다.
   - 보여 주기 전에 스스로 검토한다. 순서는 **대본과 수치 먼저, 화면은 의심 가는 곳만**이다. 문장마다 책·사양 근거를 다시 대 보고, 문장이 말하는 수치는 계산을 다시 돌려 확인한다(예: 실패한 시도를 뺀 '평균'이 실제보다 좋아 보이지 않는지). 화면은 의심 가는 장면의 프레임만 몇 장 골라 본다. 몇 초마다 프레임을 전부 뽑아 보지 않는다.
   - 한국어 표현도 검토한다. 귀로 들었을 때 어색한 곳을 찾는다: 같은 낱말의 반복(한 장면에 "만나"가 네 번), 번역투("간격에는 지연을 더합니다"), 설명 없이 쓰는 용어(나레이션의 "창"), 한 번에 따라가기 어려운 긴 문장(둘로 나눈다), 문장 가운데 뜬 인용, 주어나 목적어가 빠져 뜻이 흐린 말("둘 다 아껴 쓰면"). 화면 제목·범례·라벨의 어순도 함께 본다.
5. **나레이션**: 대본이 확정되면 그때 타입캐스트로 음성을 만든다(요청이 있을 때).
6. **미리보기 전달**: GitHub 비공개 초안(draft) 릴리스에 올려 링크를 준다.
7. **유튜브 업로드 자료**: `npm run youtube`(제목·설명·챕터·태그 `youtube.txt`, 문장별 자막 `subtitles.ko.srt`)와 `npm run thumbnail`(1920×1080로 그려 1280×720 JPG로 줄임)을 만들어 같은 초안 릴리스에 모은다. 업로드는 사용자가 직접 한다(API로 올린 영상은 심사 전까지 비공개로 잠기고, 공개 업로드는 바깥에 공개하는 일이다). 올린 주소를 받으면 서재의 영상 목록(`assets/videos.js`)에 한 줄을 더한다. 썸네일은 `assets/videos/<id>.jpg`(1280×720)로 두고, 이어진 책의 장을 `chapters`에 적으면 그 장 본문에 "영상으로 보기" 상자가 자동으로 붙는다. 유튜브에서 "퍼가기 허용"이 켜져 있는지 확인해 `embed`를 맞춘다(꺼져 있으면 서재 안에서 재생되지 않는다). 그 뒤 `python3 tools/build_search.py`로 통합 검색에 넣는다.
8. **PR**: `video/` 아래 코드와 대본을 PR로 올린다. 음성·영상 파일은 저장소에 넣지 않는다.

## 2. 내용과 사실

- **근거는 책과 사양.** 화면의 계산은 책의 함수를 그대로 옮기고(`src/book.ts`), `npm run check`가 책 원본과 같은 값을 내는지 대조한다. 서술은 책 본문이나 사양 원문에 있는 것만 쓰고, 근거 없는 일반화(예: "대부분의 기기가 그렇게 한다")는 넣지 않는다.
- **한 가지 조건의 숫자를 사실처럼 보이지 않게 한다.** 조건과 공식을 먼저 보여 주고, 숫자는 여러 조건의 예시로 보여 준다. 단순화한 가정은 해당 장면 안에서 짧게 밝힌다("겹치면 깨진다고 단순하게 보면").
- **표본을 고르지 않는다.** 무작위 시뮬레이션은 기댓값에 맞는 씨앗을 고르지 말고, 들쭉날쭉하다가 수렴하는 모습(누적 그래프)을 그대로 보여 준다.
- **용어를 정확히.** 범위가 다른 것을 하나로 말하지 않는다(예: Wi-Fi는 5 GHz도 쓰므로 "2.4 GHz Wi-Fi와 블루투스는 같은 대역"). 사양 용어는 원문으로 확인한다(예: AFH는 Classic·LE 모두 채널 맵으로 한다).
- **내용을 고치면 사용자의 지적만 따르지 말고, 사양·책으로 다시 검증한다.**

## 3. 화면

- **모든 장면은 그림·개념도·도식으로.** 글자만 있는 카드나 슬라이드는 쓰지 않는다. 설명은 시간축, 흐름도, 지도 같은 도식으로 바꾼다(예: 재전송 = 패킷이 깨지고 다시 오는 시간축, 오디오는 재생 시각을 놓쳐 끊기는 파형).
- **공간이 있는 장면은 3D와 카메라 이동으로.** 주파수 대역, 시간-채널 지도처럼 공간으로 읽히는 것은 `@remotion/three`로 만들고, 카메라가 넓게 보다가 다가가거나 내려다보거나 옆으로 미끄러지게 한다. 공식·절차는 2D 도식으로 둔다.
- **3D에는 글자를 넣지 않는다.** 제목·범례·계기판은 2D로 겹친다.
- **마지막 장면은 내용 정리.** "직접 해 보세요" 같은 권유로 끝내지 않는다. 정리 문장은 그림 위에 얹는다.
- 가로 1920×1080, 30fps를 기본으로 한다. 제목은 왼쪽 위, 자막은 아래 띠에 둔다.

## 4. 나레이션 (타입캐스트)

- **숫자는 한글로 소리 나는 대로 적는다.** `say`에는 아라비아 숫자를 쓰지 않는다. `scripts/narrate.py`가 숫자가 섞인 문장으로는 음성을 만들지 않는다.
  - 예: "2.4GHz" → "이 점 사 기가헤르츠", "14%" → "십사 퍼센트", "1번·6번·11번" → "일번, 육번, 십일번", "37개 중 31개" → "서른일곱 개 중 서른한 개"(개수는 고유어).
  - 기호도 소리로 적는다: "AFH" → "에이에프에이치", "×" → "곱하기", "≈" → "약".
- **화면 자막(`caption`)은 같은 문장을 기호·숫자로 적는다.** `say`와 `caption`은 문장 수가 같아야 하고, 자막은 나레이션이 그 문장을 읽는 동안 보인다.
- **목소리는 예슬(`tc_66ab0e26ec23f325b7ad51df`)로 통일한다.** `narrate.py`의 기본값이다. 목소리를 바꾸면 모든 장면을 다시 만든다(장면마다 목소리가 섞이지 않게).
- **감정은 프리셋으로 고정한다(`normal`).** 자동 감정(SmartPrompt)은 장면마다 톤이 튀었다.
- **음성을 후처리로 바꾸지 않는다.** 높이·속도를 바꾸면 소리가 이상해진다. 한 장면의 톤이 튀면 그 장면만 `--redo`로 다시 만들고, 필요하면 `--emotion`으로 프리셋을 바꾼다. 음 높이(F0)를 재서 다른 장면과 비교하면 판단이 쉽다.
- **타입캐스트는 무료 계정이다.** 실패해도 자동으로 다시 부르지 않는다. 이미 있는 장면 음성은 다시 만들지 않는다.
- **음량은 −16 LUFS로 맞춘다**(`npm run loudnorm`). 영상은 다시 인코딩하지 않는다.

## 5. 시간

- **짧을수록 좋다.** 내용이 모자랄 때만 3분까지 늘린다.
- 나레이션판의 장면 길이는 음성 길이 + 여백(앞 0.3초, 뒤 0.6초)으로 맞추고, 애니메이션이 다 보이는 최소 길이보다 줄이지 않는다.
- **화면 변화는 나레이션의 문장 시각에 맞춘다.** `narrate.py`가 음성의 쉼을 찾아 문장 시작 시각(`cues`)을 기록한다. 막대가 올라오는 순간, 장면 전환 같은 변화는 그 문장을 읽기 시작할 때 일어나게 한다.
- 화면 진행이 나레이션보다 느리면 장면을 줄이고 애니메이션을 빠르게 한다.

## 6. 구조와 도구

- 한 영상 = `src/<영상>/` 폴더 하나: `script.ts`(장면, `say`·`caption`), 장면 조립 컴포넌트, `timing.ts`(장면 길이·문장 시각, 영상과 업로드 자료가 함께 씀), `durations.json`(음성 길이·문장 시각·문장, `narrate.py`가 씀), `youtube.ts`(제목·설명·챕터 묶음·태그), `Thumbnail.tsx`.
- 유튜브 챕터는 장면을 묶어 정한다. 첫 챕터 0:00, 3개 이상, 각 10초 이상이어야 하며 `npm run youtube`가 검사한다.
- 공통: `src/book.ts`(책 계산), `src/theme.ts`(색·글꼴), `public/fonts/`(Pretendard, OFL).
- `npm run check`: 책과의 대조, 영상이 말하는 수치, `say`·`caption` 문장 수, 음성이 지금 대본으로 만든 것인지 확인한다.
- 3D는 GPU 없는 NAS에서 SwiftShader(`swangle`)로 그린다. 렌더링이 느리므로 정지 화면(`remotion still`)으로 장면을 먼저 확인한 뒤 전체를 렌더한다.
- 무음판(`<영상>`)과 나레이션판(`<영상>Voice`) 컴포지션을 둘 다 둔다.
