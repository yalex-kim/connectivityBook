# 영상 제작 규칙

ConnectivityBook 내용으로 영상을 만들 때 따르는 규칙이다. 첫 영상("블루투스는 왜 AFH가 필요할까")을 만들며 받은 피드백을 정리했다. 새 영상도 이 순서와 기준으로 만들고, 규칙을 바꿀 일이 생기면 이 문서를 먼저 고친다.

## 1. 진행 순서

1. **주제와 메시지 정하기**: 책의 한 장에서 "왜 그런가"를 하나 고른다. 숫자 하나가 아니라 원리·메커니즘이 메시지가 되게 한다(예: "42%를 잃는다"가 아니라 "AFH가 왜 필요한가").
2. **제목·훅 제안 → 선택**: 훅 후보를 여러 개 내고 사용자가 고른다. 실제 생활 장면(기기들을 함께 쓰는 방 등)으로 여는 것이 잘 맞았다.
   - **제목은 시청자가 실제로 품는 질문으로.** 시청자가 모르는 사실을 전제하지 않는다. 「블루투스는 왜 두 가지일까?」는 "사람들은 두 가지인지도 모를걸"이라는 이유로 바뀌었다(→ 「같은 블루투스인데 왜 다르게 말할까?」).
   - **가장 흔한 경험으로 연다.** 페어링 숫자는 키보드보다 차에서 겪는 사람이 많았다(→ 「차는 숫자를 확인하는데, 이어폰은 왜 그냥 연결될까?」). 사용자의 경험과 다르면 그쪽을 따른다.
   - **모든 장면이 훅의 질문에 답해야 한다.** 질문에서 벗어나는 소재(역사, 이름의 유래, 버전 상식)는 재미있어도 뺀다. 구성안은 "질문 → 답의 첫마디 → 이유들 → 질문에 답하며 정리"의 흐름인지 본다.
3. **구성안 검토**: 장면별 화면·나레이션을 표로 정리해 확인받는다.
4. **무음판**: 화면과 자막만으로 렌더해 보여 준다. 고칠 점을 받아 반영한다. 사용자가 원하면 건너뛰고 구성안 확인 뒤 바로 나레이션판을 만든다(입문 1~10편은 이렇게 했다). 건너뛰어도 아래 자체 검토는 나레이션을 만들기 전에 한다.
   - 보여 주기 전에 스스로 검토한다. 순서는 **대본과 수치 먼저, 화면은 의심 가는 곳만**이다. 문장마다 책·사양 근거를 다시 대 보고, 문장이 말하는 수치는 계산을 다시 돌려 확인한다(예: 실패한 시도를 뺀 '평균'이 실제보다 좋아 보이지 않는지). 화면은 의심 가는 장면의 프레임만 몇 장 골라 본다. 몇 초마다 프레임을 전부 뽑아 보지 않는다.
   - 한국어 표현도 검토한다. 귀로 들었을 때 어색한 곳을 찾는다: 같은 낱말의 반복(한 장면에 "만나"가 네 번), 번역투("간격에는 지연을 더합니다"), 설명 없이 쓰는 용어(나레이션의 "창"), 한 번에 따라가기 어려운 긴 문장(둘로 나눈다), 문장 가운데 뜬 인용, 주어나 목적어가 빠져 뜻이 흐린 말("둘 다 아껴 쓰면"). 화면 제목·범례·라벨의 어순도 함께 본다.
5. **나레이션**: 대본이 확정되면 그때 타입캐스트로 음성을 만든다(요청이 있을 때).
6. **미리보기 전달**: GitHub 비공개 초안(draft) 릴리스에 올려 링크를 준다.
7. **유튜브 업로드 자료**: `npm run youtube`(제목·설명·챕터·태그 `youtube.txt`, 문장별 자막 `subtitles.ko.srt`)와 `npm run thumbnail`(1920×1080로 그려 1280×720 JPG로 줄임)을 만들어 같은 초안 릴리스에 모은다. API로는 올리지 않는다(심사 전까지 비공개로 잠긴다). 공개 업로드는 바깥에 공개하는 일이므로, 사용자가 "올려 달라"고 한 영상만 사용자의 휴대폰(YouTube 앱, 채널 계정)으로 올린다. 아래 "휴대폰 업로드"를 따른다. 올린 주소를 받으면 서재의 영상 목록(`assets/videos.js`)에 한 줄을 더한다. 썸네일은 `assets/videos/<id>.jpg`(1280×720)로 두고, 이어진 책의 장을 `chapters`에 적으면 그 장 본문에 "영상으로 보기" 상자가 자동으로 붙는다. 유튜브에서 "퍼가기 허용"이 켜져 있는지 확인해 `embed`를 맞춘다(꺼져 있으면 서재 안에서 재생되지 않는다). 그 뒤 `python3 tools/build_search.py`로 통합 검색에 넣는다.
   - **휴대폰 업로드**: 만들기 → 동영상 → 갤러리에서 파일 고르기 → 다음. 세부정보에서 제목, 썸네일(연필 → 변경 → 최근 이미지), 설명(`youtube.txt` 전문), 속성 → 태그, AI 사용을 채운다. 공개 상태는 공개, 시청자층은 아동용 아님.
     - **썸네일은 매번 화면으로 확인한다.** 최근 이미지는 파일을 만든 순서로 놓여서, 썸네일 하나를 다시 만들면 순서가 바뀐다. 7편에 8편 썸네일이 들어갈 뻔했다.
     - **타입캐스트 표기**: 무료 플랜으로 만든 음성은 타입캐스트 정책에 따라 설명문에 한·영 표기(서비스 이름, 출연진 = 쓴 캐릭터 이름 모두, 주소)를 넣는다. `npm run youtube`가 설명문 끝에 붙인다. 캐릭터가 예슬(Yeseul)이 아니거나 여럿이면 `youtube.ts`의 `cast`에 [한국어, 영문] 이름을 모두 적는다.
     - **AI 사용**: 실제 인물이 하지 않은 말·행동, 실제 사건·장소 변경, 진짜처럼 보이는 가짜 장면, 주요 음악 생성이 아니면 "아니요". 나레이션이 AI 음성이라는 것은 설명란 끝(credits)에 적는다.
     - 업로드가 진행 중일 때 YouTube 앱을 강제 종료하지 않는다(업로드가 끊길 수 있다).
     - 올린 영상의 주소는 채널 동영상 페이지에서, 길이는 영상 페이지의 `lengthSeconds`에서 확인한다. 이미 올린 영상의 설명·제목 수정은 YouTube Studio 앱(콘텐츠 → 메뉴 → 수정)으로 한다. 내용이 같으면 저장 버튼이 켜지지 않는다.
   - **서재 등록 필드**: `assets/videos.js`의 `series`(묶음 이름)·`no`(편 번호)로 서재에서 묶고 순서를 정한다. 장 링크의 `short`(예: "입문 6장")가 카드에 보인다. 영상은 서재 첫 화면이 아니라 **책 홈**에 보인다: 책의 `book.json` `ui.videos`에 보일 묶음 이름을 순서대로 적으면(블루투스 입문편은 입문→심화, 심화편은 심화→입문) `shared/common.js`가 목차 앞에 영상 묶음을 그린다. 새 책의 영상 묶음을 만들면 그 책의 `ui.videos`에 더하고 `sync_shared.py`를 돌린다.
   - **앞 영상을 말하면 카드를 단다.** 나레이션이 "입문편 다섯 번째 영상에서…"처럼 다른 영상을 부르면, 그 문장이 시작할 때 오른쪽 위 카드(티저 "지난 영상 보기")로 그 영상을 잇는다. `youtube.ts`의 `cards`에 적으면 `npm run youtube`가 시각을 계산해 `youtube.txt`의 [카드]에 쓴다. 카드는 YouTube Studio(편집기 → 카드)에서 단다. 화면에 같은 글자를 그려 넣지 않는다(카드 티저와 겹친다).
   - **업로드 직후 책 링크 댓글을 단다.** 채널 계정(ConnBook TV)으로 이어지는 책 장 링크를 댓글로 달고 고정한다. 댓글을 다는 앱의 계정이 채널 계정인지 먼저 확인한다(영상 화면에 '구독' 버튼이 보이면 다른 계정이다). 댓글 고정은 채널의 고급 기능 인증이 끝나야 된다.
8. **PR**: `video/` 아래 코드와 대본을 PR로 올린다. 음성·영상 파일은 저장소에 넣지 않는다.

## 2. 내용과 사실

- **근거는 책과 사양.** 화면의 계산은 책의 함수를 그대로 옮기고(`src/book.ts`), `npm run check`가 책 원본과 같은 값을 내는지 대조한다. 서술은 책 본문이나 사양 원문에 있는 것만 쓰고, 근거 없는 일반화(예: "대부분의 기기가 그렇게 한다")는 넣지 않는다.
- **한 가지 조건의 숫자를 사실처럼 보이지 않게 한다.** 조건과 공식을 먼저 보여 주고, 숫자는 여러 조건의 예시로 보여 준다. 단순화한 가정은 해당 장면 안에서 짧게 밝힌다("겹치면 깨진다고 단순하게 보면").
- **표본을 고르지 않는다.** 무작위 시뮬레이션은 기댓값에 맞는 씨앗을 고르지 말고, 들쭉날쭉하다가 수렴하는 모습(누적 그래프)을 그대로 보여 준다.
- **용어를 정확히.** 범위가 다른 것을 하나로 말하지 않는다(예: Wi-Fi는 5 GHz도 쓰므로 "2.4 GHz Wi-Fi와 블루투스는 같은 대역"). 사양 용어는 원문으로 확인한다(예: AFH는 Classic·LE 모두 채널 맵으로 한다).
- **조건에 따라 달라지는 말은 모든 경우에 맞는지 확인한다.** "보낸 세기의 십억분의 일보다 약해도 듣는다"는 송신 0 dBm에서는 맞지만 −20 dBm 태그에서는 틀려서, 음성을 만들기 전에 뺐다.
- **기술의 범위를 넓게 말하지 않는다.** "모든 LE 기기는 GATT를 쓴다"가 아니라 "작은 값을 주고받는 LE 기기들은 대부분 GATT 위에서"처럼 말한다. 음악·통화 프로파일은 GATT를 쓰지 않는다. 계산으로 설명이 맞아떨어지는지도 본다(1 m 거리에서 몸이 깎는 손실만으로는 끊기지 않아서 반사파를 함께 말했다).
- **책의 오류를 찾으면 따로 고친다.** 영상의 수치를 책 함수로 다시 계산하다 책 본문과 맞지 않는 곳을 찾으면, 근거를 확인해 사용자에게 알리고 책 수정은 별도 PR로 낸다(예: 2장의 "1 mW는 3 m에서 10억분의 1" → 자유 공간 손실 식으로 10만분의 1, PR #44).
- **내용을 고치면 사용자의 지적만 따르지 말고, 사양·책으로 다시 검증한다.**

## 3. 화면

- **모든 장면은 그림·개념도·도식으로.** 글자만 있는 카드나 슬라이드는 쓰지 않는다. 설명은 시간축, 흐름도, 지도 같은 도식으로 바꾼다(예: 재전송 = 패킷이 깨지고 다시 오는 시간축, 오디오는 재생 시각을 놓쳐 끊기는 파형).
- **공간이 있는 장면은 3D와 카메라 이동으로.** 주파수 대역, 시간-채널 지도처럼 공간으로 읽히는 것은 `@remotion/three`로 만들고, 카메라가 넓게 보다가 다가가거나 내려다보거나 옆으로 미끄러지게 한다. 공식·절차는 2D 도식으로 둔다.
- **3D에는 글자를 넣지 않는다.** 제목·범례·계기판은 2D로 겹친다. 3D 물체 옆에 붙는 라벨은 3D 좌표를 화면에 투영해 놓는다(`range/hook3d.tsx`의 `project`).
- **사람과 기기는 3D로.** 평면 SVG로 그린 사람·휴대폰은 투박해 보였다. 캡슐 몸·공 머리 같은 단순한 3D 형태에 안개와 조명을 더하고, 몸을 지나는 신호는 반투명 재질로 보이게 한다. 훅과 정리 장면에 특히 쓴다.
- **프로토콜 용어에는 화면 설명 상자를 단다.** NESN, CCCD, ppm, FT처럼 화면에 나오는 용어는 그 도식 위에 2~3줄 설명 상자(`common/kit.tsx`의 `Note`)를 붙인다. 나레이션은 바꾸지 않아도 된다. 글자만 있는 카드와 달리 도식에 딸린 풀이라 허용한다.
- **정지 화면으로 겹침을 확인한다.** 장면마다 마지막 상태를 한 장씩 뽑아 라벨끼리, 라벨과 막대·자막이 겹치지 않는지 본다. 좁은 막대의 라벨은 위아래로 번갈아 놓거나 이름을 줄인다.
- **마지막 장면은 내용 정리.** "직접 해 보세요" 같은 권유로 끝내지 않는다. 정리 문장은 그림 위에 얹는다.
- 가로 1920×1080, 30fps를 기본으로 한다. 제목은 왼쪽 위, 자막은 아래 띠에 둔다.

## 4. 나레이션 (타입캐스트)

- **숫자는 한글로 소리 나는 대로 적는다.** `say`에는 아라비아 숫자를 쓰지 않는다. `scripts/narrate.py`가 숫자가 섞인 문장으로는 음성을 만들지 않는다.
  - 예: "2.4GHz" → "이 점 사 기가헤르츠", "14%" → "십사 퍼센트", "1번·6번·11번" → "일번, 육번, 십일번", "37개 중 31개" → "서른일곱 개 중 서른한 개"(개수는 고유어).
  - 기호도 소리로 적는다: "AFH" → "에이에프에이치", "×" → "곱하기", "≈" → "약".
- **쉼은 쉼표로 표시한다.** 타입캐스트는 구절을 붙여 읽는다("나눠 느리고 꼼꼼하게" → "나눠, 느리고 꼼꼼하게"). 쉼을 고치면 그 장면만 `--redo`로 다시 만든다.
- **약어는 읽는 소리를 정해 두고 같은 소리로 쓴다**: LE → 엘이, GATT → 개트, A2DP → 에이투디피, Just Works → 저스트 웍스. 0x180D 같은 16진수 번호는 나레이션에서 읽지 않고 자막과 설명 상자로만 보여 준다.
- **화면 자막(`caption`)은 같은 문장을 기호·숫자로 적는다.** `say`와 `caption`은 문장 수가 같아야 하고, 자막은 나레이션이 그 문장을 읽는 동안 보인다.
- **목소리는 예슬(`tc_66ab0e26ec23f325b7ad51df`)로 통일한다.** `narrate.py`의 기본값이다. 목소리를 바꾸면 모든 장면을 다시 만든다(장면마다 목소리가 섞이지 않게).
- **감정은 프리셋으로 고정한다(`normal`).** 자동 감정(SmartPrompt)은 장면마다 톤이 튀었다.
- **음성을 후처리로 바꾸지 않는다.** 높이·속도를 바꾸면 소리가 이상해진다. 한 장면의 톤이 튀면 그 장면만 `--redo`로 다시 만들고, 필요하면 `--emotion`으로 프리셋을 바꾼다. 음 높이(F0)를 재서 다른 장면과 비교하면 판단이 쉽다.
- **타입캐스트는 무료 계정이다.** 실패해도 자동으로 다시 부르지 않는다. 이미 있는 장면 음성은 다시 만들지 않는다.
- **음량은 −16 LUFS로 맞춘다**(`npm run loudnorm`). 영상은 다시 인코딩하지 않는다.

## 5. 시간

- **짧을수록 좋다.** 내용이 모자랄 때만 3분까지 늘린다.
- 나레이션판의 장면 길이는 음성 길이 + 여백(앞 0.3초, 뒤 0.6초)으로 맞추고, 애니메이션이 다 보이는 최소 길이보다 줄이지 않는다.
- **화면 변화는 나레이션의 문장 시각에 맞춘다.** `narrate.py`가 음성의 쉼을 찾아 문장 시작 시각(`cues`)을 기록한다. 막대가 올라오는 순간, 장면 전환 같은 변화는 그 문장을 읽기 시작할 때 일어나게 한다.
- 화면 진행이 나레이션보다 느리면 장면을 줄이고 애니메이션을 빠르게 한다.

## 6. 구조와 도구

- 한 영상 = `src/<영상>/` 폴더 하나: `script.ts`(장면, `say`·`caption`), 장면 조립 컴포넌트, `timing.ts`(장면 길이·문장 시각, 영상과 업로드 자료가 함께 씀), `durations.json`(음성 길이·문장 시각·문장, `narrate.py`가 씀), `youtube.ts`(제목·설명·챕터 묶음·태그), `Thumbnail.tsx`.
- 유튜브 챕터는 장면을 묶어 정한다. 첫 챕터 0:00, 3개 이상이어야 한다. 적는 시각은 초 단위로 올림하고, 각 구간은 **10초보다 길어야** 한다. 딱 10초인 첫 구간은 유튜브가 챕터로 인식하지 않았다. `npm run youtube`가 검사하니, 짧은 장면은 다음 장면과 한 챕터로 묶는다.
- 공통: `src/book.ts`(책 계산), `src/theme.ts`(색·글꼴), `src/common/kit.tsx`(3D 바닥 `Ground`, 설명 상자 `Note`, 장면 틀 `makeVideo`, 썸네일 틀 `ThumbCard`. 심화 시리즈는 `deep`을 켠다: 배치는 입문과 같고, 심화 책의 인디고색·왼쪽 세로 띠·"심화" 표지로 구분한다), `public/fonts/`(Pretendard, OFL). 새 영상은 `makeVideo`로 장면을 이어 붙인다.
- `npm run check`: 책과의 대조, 영상이 말하는 수치, `say`·`caption` 문장 수, 음성이 지금 대본으로 만든 것인지 확인한다.
- 3D는 GPU 없는 NAS에서 SwiftShader(`swangle`)로 그린다. 렌더링이 느리므로 정지 화면(`remotion still`)으로 장면을 먼저 확인한 뒤 전체를 렌더한다.
- 무음판(`<영상>`)과 나레이션판(`<영상>Voice`) 컴포지션을 둘 다 둔다.
